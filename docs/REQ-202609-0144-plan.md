# 提交页新增「反馈与建议」— 技术方案

需求编号：REQ-202609-0144
分支：`req-202609-0144`

## 一、需求复述

提交页顶部的 tab 条原本只有两项：「失踪信息提交」「线索提供」。现在要加第三项「反馈与建议」，让访客把对平台的建议、问题、反馈直接发给运营方。具体要求：

1. 表单只有**两个字段**：标题 + 反馈内容。
2. 前台任何访客都能提交，**不强制登录**（失踪信息、线索两项同样不强制登录，本次一并确认）。
3. 后台要能看见这些反馈。
4. **不能重复提交**：点了提交按钮后按钮要锁住，防止连点、防止重复打接口。
5. **不能传图片**，只能文字描述。
6. 内容输入框初始高度比默认略高一点（但别太高，高了难看），用户可以自己拖拽调高度，文本超出高度时框内滚动。

## 二、现状

- `src/app/submit/page.tsx` 是一个客户端组件，用 `const [tab, setTab] = useState<Tab>("missing")` 在「失踪信息提交 / 线索提供」两套表单之间切换，tab 条是两个写死的 `<button>`，下面用三元表达式分支渲染两套表单。
- 两个表单都不校验登录态，未登录访客可以直接提交 —— 需求里「不强制登录」这一条现状已经满足，本次不改登录逻辑。
- 最接近「访客提交 + 后台审核」的先例是**线索**：`src/app/api/clues/route.ts`（公开 POST）→ `clues` 表 → `src/app/api/admin/clues/route.ts`（带鉴权）→ `/admin/clues` 列表页 → 后台侧边栏「内容管理」分组。本次整体照这条竖切复制。
- 重复提交的既有写法：线索表单的 `clueSubmitting` state + `disabled={clueSubmitting}` + `finally` 复位。
- 共享的 `Textarea` 组件（`src/components/ui/Input.tsx`）写死了 `resize-none` 和 `rows={4}`，而 `cn()` 是 `classes.filter(Boolean).join(" ")`（不是 tailwind-merge），后传入的 `resize-y` 能不能覆盖取决于 Tailwind 生成 CSS 的顺序 —— **不可靠**，所以反馈表单用原生 `<textarea>` 自己写 class。

## 三、设计

### 3.1 建表与建表时机

新增 `feedback` 表，字段刻意只有必要的几个：`id / title / content / user_id / user_name / status / created_at`。**没有图片字段**，从数据模型上就杜绝上传图片这个口子。

建表走项目既有的双轨约定：

- `src/instrumentation.ts` 在 Node 运行时启动时调用 `initDb()`，`initDb()`（`src/lib/db/index.ts`）里存着 docker 平台的裸 DDL。把 `CREATE TABLE IF NOT EXISTS feedback` 和两个索引加进去，**服务一重启表就自动建好**，不需要人工上库执行 SQL。
- 同时补一份 `drizzle/0004_feedback.sql` 作为记录在案的迁移，跟 `0003_site_visits.sql` 保持一致。

索引建在 `status` 和 `created_at` 上：后台列表按状态筛 + 按时间倒序，这两个正好覆盖。

### 3.2 提交接口：公开、可选身份

`POST /api/feedback`（`src/app/api/feedback/route.ts`）不校验登录。身份信息是**可选增强**：调 `getUserFromRequest(request)`，登录了就把 `userId` / `userName` 一起落库（后台能看出是谁提的），没登录两者为 `null`（后台显示「游客」）。接口不因为没有登录态而拒绝请求。

入参校验在服务端兜底：标题、正文各自 `trim()` 后不能为空；长度上限前后端共用一个常量（`FEEDBACK_TITLE_MAX = 100`、`FEEDBACK_CONTENT_MAX = 2000`，放在 `src/lib/constants.ts`），前端只是 `maxLength` 截断，真正的闸门在后端。错误文案走 `apiError(request, key, status)`，`feedbackFieldsRequired / feedbackTitleTooLong / feedbackTooLong` 三个 key 加进 `src/lib/i18n/api-messages.ts`（中英）。

`id` 用 `uuid` 生成，返回 `201 { id }`，前端只看状态码。

### 3.3 后台接口：只读列表 + 状态流转

`src/app/api/admin/feedback/route.ts`，`GET`（分页 + 可选 `status` 筛选）和 `PATCH`（切换 `pending` / `handled`）。两个方法**各自**调 `getAdminFromCookies()` 判 401 —— 因为 `src/proxy.ts` 的 matcher 排除了 `/api`，API 路由不会被中间件挡住，鉴权必须写在每个 handler 里。

### 3.4 前台表单的三个交互点

**(a) 防重复提交**：`feedbackSubmitting` state 既喂给按钮的 `disabled`，也在 handler 开头做 `if (feedbackSubmitting) return` 的早退。两层是互补的 —— `disabled` 挡正常点击，早退挡「禁用生效前那一帧已经排进队列的第二次调用」。按钮文案同时切成「提交中…」，让用户看得见按下去了。请求走 `finally` 复位，失败也能再点。

**(b) 输入框尺寸**：原生 `<textarea rows={6}>`，实测初始高度 148px —— 比默认的 4 行高一点，又不到半屏，符合「大一点点，别太大」。`min-h-[140px] max-h-[420px]` 限住拖拽范围。

**(c) 可拖拽 + 内部滚动**：`resize-y` 让右下角出现拖拽把手（只放开高度，宽度跟着栅格走，避免拖歪版式）；`overflow-y-auto` 保证文本超过框高时**框内**出滚动条，而不是把页面越撑越长。附带 `maxLength` + 右下角提示「暂不支持上传图片，文字描述即可」。

### 3.5 tab 条重构

两个写死的按钮改成数组 `.map()` 出三个，`Tab` 类型扩成 `"missing" | "clue" | "feedback"`。渲染分支从二元三元改成链式三元。这样以后再加 tab 只改数组。

### 3.6 文案

11 个新 key（`tabFeedback`、`feedbackSubtitle`、`feedbackTitleLabel` … `feedbackContentRequired`）加进 `src/lib/i18n/public/zh.ts`（`PublicTranslations` 的源头），另外 9 个语言包（`zh-hant / en / ja / ko / fr / de / ug / mn / bo`）都按这个类型标注，所以**每个包都必须补齐**，否则 type check 直接挂。

## 五、验收标准

1. 提交页 tab 条三项，点击「反馈与建议」切到反馈表单；另两项行为不变。
2. 反馈表单只有标题输入框和正文 textarea，**整页没有任何 file input**。
3. 正文框初始高度比默认略高；可拖拽调高；文本超出时框内滚动、不撑长页面。
4. 未登录访客能提交成功，落库 `user_id/user_name` 为 null；已登录提交能记下提交人。
5. 连点提交按钮只发**一次**请求，飞行中按钮为 disabled。
6. 后台 `/admin/feedback` 能看到提交内容，可按 全部/待处理/已处理 筛选，能标记已处理 / 重新打开。
7. 未带管理员 Cookie 访问后台接口返回 401。
8. `tsc --noEmit` 通过；`eslint` 不新增问题（基线 86 errors / 30 warnings）；`next build` 通过。
