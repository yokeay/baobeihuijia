# 分享卡兜底：无有效照片时生成动态分享图 — 技术方案与交付记录

需求编号：REQ-202610-0443
分支：`req-202610-0443`
依据：`docs/REQ-202610-0267-development-roadmap.md` 卡 15（阶段二 · 触达 · 预估小 · P2）
前置关联：卡 05「照片可用性巡检与裂图兜底」（失效检测本卡先做「分享时兜底」，巡检另行立项）

## 一、需求复述

【现状】案件页的 OG 图（`openGraph.images` / `twitter.images`）**直接使用案件照片**：有绝对地址就热链上游，无照片时整条 `images` 为空、分享卡无图；韩国大量记录无可用照片（上游只对最近几十条稳定供图，更早的返回占位图）。西班牙 CNDES 照片是**应用内相对地址**（`/api/image/cndes/...`），微信 / X 的抓取器拿相对地址也取不到图。

【目标】为**无有效照片**的案件生成品牌化动态分享图（姓名 / 地区 / 站点标识），**不改变肖像使用口径**（有照片的仍按原策略热链，不做裁剪、不做转存）。

【验收】无照片案件在微信 / X 等平台分享时展示兜底图。

| --- | --- | --- | --- | --- |
| 中国大陆 | `cases` | 46,909 | 46,732 | 177（`[null]` 176 + 相对 1） |
| 美国 | `cases_us` | 26,594 | 20,685 | 5,909（`[]` / null） |
| 香港 | `cases_hk` | 40 | 40 | 0 |
| 韩国 | `cases_kr` | 1,043 | 0 | 1,043（`/api/image/safe182/*`，其中 789 条有字段但上游多为占位图） |
| 西班牙 | `cases_es` | 525 | 0 | 525（`/api/image/cndes/*.png|jpg`，其中 4 条 BMP） |

口径：热链 = `photo_urls` 首项以 `http(s)://` 开头；兜底 = 无照片，或首项是应用内相对地址（社交抓取器无法解析相对地址，且韩国相对地址背后可能是占位图 / 已失效）。

## 三、设计

思路：**做分流，而不是替换**。有可热链的绝对照片的案子维持原样（保住大陆 4.6 万 + 美国 2 万张图，也避免把 7 万张照片的抓取流量引到本站服务器、避免美国 NamUs 按 IP 封禁）；其余案子把 OG 图指向一条**运行时生成**的品牌卡路由。

### 3.1 分流：`src/lib/case-share-image.ts`（新增）

```ts
export function caseShareImageUrl(c: { id: string; photoUrls?: string | null }): string {
  const photo = firstPhotoUrl(c.photoUrls);
  if (photo && /^https?:\/\//i.test(photo)) return photo;      // 绝对地址：热链原样
  return `${SITE_ORIGIN}/api/og/case/${encodeURIComponent(c.id)}`; // 其余：生成卡
}
```

`src/app/case/[id]/page.tsx` 的 `generateMetadata` 改用这一个函数同时喂 `openGraph.images` 与 `twitter.images`（`twitter.card` 保持 `summary_large_image`）。删掉了原先只算一次 `firstPhotoUrl` 的局部变量。JSON-LD 的 `image` 未改（仍是热链照片或留空，属页面结构化数据、非分享卡，不在本卡范围）。

### 3.2 生成卡路由：`src/app/api/og/case/[id]/route.tsx`（新增）

- `export const runtime = "nodejs"`；用 `next/og` 的 `ImageResponse`，1200×630，Satori + Resvg 渲染。本机装有 Noto CJK 系统字体，中 / 韩文正常出字（已实测）。
- 案件不存在 → 404 `Not found`；命中 → PNG，带 `Cache-Control: public, max-age=3600, s-maxage=86400`（首次生成后由 CDN / 抓取器缓存，降低每次分享都跑一遍渲染）。
- 布局：左侧文字列（IMU 品牌块 +「我好想你 / I MISS YOU」+ 姓名 + 地区 + 品牌红下划线 + 页脚「全球失踪人口信息聚合公益平台 · 永久免费」+ `wohaoxiangni.com`），**姓名按长度自适应字号**（>20 字 54px、>10 字 68px、否则 92px），防止拉丁 / 韩文长姓名溢出。

### 3.3 照片解析：不再自请求 HTTP，改为「能本地拿到的才嵌」

兜底卡**不是**简单画个纯文字卡：相对地址的案子仍尽量把照片嵌进右侧 440px 面板。取图**不去 `fetch` 自己的 relay 路由**（那是绕圈请求），而是按来源分两种：

- 韩国 `/api/image/safe182/<id>` → 直接调 `fetchSafe182Image(id)`（relay 路由内部同一个函数），命中即内联为 `data:` URL，返回 null 就用纯文字卡（老记录上游给占位图，`fetchSafe182Image` 已能识别）。
- 西班牙 `/api/image/cndes/<md5>.<ext>` → 从 `public/uploads/cndes/` 读盘。**只内联 png / jpg**：卡片渲染器解不了 CNDES 的 BMP，硬塞会让整张卡渲染失败，宁可退回纯文字卡。
- 绝对地址一律**不在此路由取**（那些案子根本不会走到这条路由）。

### 3.4 与卡 05 的关系

卡 15 是**分享时兜底**：抓取器拿图那一刻解析不出有效照片，就给品牌卡，分享永远不会是空白。卡 05 的**周期性全量巡检 + 裂图占位**是另一件事（抽样 HEAD / 占位图识别、打标记、界面兜底、出报告），本次不做，留给卡 05。两者共用「占位图识别」这一能力（`fetchSafe182Image`）。

## 四、验收（实测）

在 worktree 起 `next start -p 3999` 逐类打样（下列为实际结果）：

| 样本 | 类型 | 结果 |
| --- | --- | --- |
| `8268157c-…`（CN 静静，`[null]`） | 无照片 | 200 `image/png`，品牌纯文字卡：IMU + 静静 + 山东省·青岛市 |
| `ff0e0d86-…`（CN，`https://so.baobeihuijia.com/…`） | 热链 | 页面 `og:image` 与 `twitter:image` 均为**原绝对 CDN 地址**，未改 |
| `45ca5fde-…`（ES Dounia L.） | CNDES 相对地址 | 200 `image/png`，右侧嵌入照片（落盘后 42KB → 503KB） |
| `972760ee-…`（KR 임씨，safe182/437625） | 相对地址 + 上游占位图 | 200 `image/png`，纯文字卡（relay 对该 id 实测 404，故正确兜底） |
| `does-not-exist` | 不存在 | 404 `text/plain` `Not found` |

页面元数据抽查（`curl http://127.0.0.1:3999/case/<id>`）：
- 无照片案子 → `og:image` / `twitter:image` = `https://wohaoxiangni.com/api/og/case/<id>`。
- 热链案子 → 二者均为上游绝对地址，与改动前一致。

工程校验：`npx tsc --noEmit` 0 错；`npm run lint` 116 问题（86 errors / 30 warnings），与改动前基线**完全一致**（未新增）。

> 平台侧真正「发到微信 / X 看卡片」无法在无头环境自动验收：微信分享卡走 JS-SDK + 服务端抓取缓存、X 走 Card Validator，均需人工在真机 / 平台工具触发一次。本次交付的是这条链路的数据前提（正确、可抓取的绝对 `og:image` URL + 该 URL 实测 200 `image/png`）。

## 六、遗留（需人工）

- **真机分享验收**：微信 / X 各发一次无照片案子的链接，确认展示兜底卡（见第四节说明，无头环境替代不了）。
- **渲染耗时**：Satori 渲染一张约数百毫秒级（含取图）；已加 CDN 缓存头，首次生成后的重复分享由缓存扛。若线上分享量上来、或抓取器不尊重缓存，可再评估预热或缓存层。
- **卡 05 未做**：全量巡检、裂图占位、失效标记仍属卡 05；本卡只在**分享卡**这一处兜底，页面内 `<img>` 的裂图兜底不在本卡范围。
