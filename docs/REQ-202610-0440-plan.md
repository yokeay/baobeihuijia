# 西班牙数据源接入：CNDES（约 525 条）— 技术方案与交付记录

需求编号：REQ-202610-0440
分支：`req-202610-0440`
上游：西班牙内政部失踪人口与失踪者国家中心（CNDES）
`https://cndes-web.ses.mir.es/publico/Desaparecidos/`

## 一、需求复述

把西班牙官方失踪人口库 CNDES 接入平台，与港、美、韩三国同构：新建独立地区表、全量同步入库、照片可用、后台可手动触发，并在 `SYNCED_COUNTRIES` 注册使其进入检索 / 统计 / 详情。验收口径（来自 `docs/REQ-202610-0267-development-roadmap.md` 卡 12）：

> 全量同步成功入库，照片可用、姓名展示符合源站口径。

需求点明三处必须注意的坑：**`start=0` 必须显式传**、**单次查询硬上限 100 条**、**单次响应可达 27.6MB**。

## 二、上游实测（2026-10-13 复测）

| 项 | 值 |
| --- | --- |
| 列表接口 | `POST https://cndes-web.ses.mir.es/publico/Desaparecidos/dao/ServletDesaparecidos` |
| 请求体 | `operacion=buscar&start=0&max=100&locale=es[&anioDesaparecido=YYYY]`（`application/x-www-form-urlencoded`） |
| 返回 | JSON，`{totalRegistros, desaparecidos[]}` |
| 总量 | `totalRegistros = 525`（无过滤），实测与年份切片求和一致 |
| 字段 | `id` / `nombreCompleto` / `genero` / `tipoDesaparecido`（MENOR/ADULTO/MAYOR）/ `fechaDesaparicion`（`YYYY-MM-DD`）/ `resumenWeb` / `necesidades` / `cuerpo` / `telefono` / `tipoAlerta` / `localizado` / `foto`（base64 内联） |
| 详情页 | `.../Desaparecidos/Detalle-Desaparecido.html?desaparecido=<id>`（HTTP 200，按 id 客户端渲染） |
| robots | 该路径无限制（`/publico/` 下未被 Disallow） |

**三处坑的落实**：

1. **`start` 不是偏移量**。留空会返回 `{"aviso":"Error interno..."}`；显式 `start=0` 才出数据；而 `start=100` 直接返回空 —— 即该接口**只认第一页**。因此年份切片不是「为省流量」，而是枚举全量的**唯一**途径。代码里 `start: "0"` 写死。
2. **年份切片完整**。年份区间 1974–2026，逐年查询求和 = 525（= `totalRegistros`），单年最大 88 条（2026）远低于 100 上限。代码在 `fetchYear` 里对「返回条数 ≥ 100」直接抛错，让将来某年超限时**报错而非静默截断**。
3. **响应体积**。100 条 ≈ 27.6MB（照片内联 base64，单张平均 ~218KB，全量解码约 112MB）。按年切片天然摊平了单次体积。

**数据形态**（全量 525）：

- `genero`：Hombre 393 / Mujer 132；`tipoDesaparecido`：ADULTO 309 / MENOR 133 / MAYOR 83
- `fechaDesaparicion`：全部长度 10 的 ISO 日期，可直接作 `lost_date`（满足 NOT NULL）
- `localizado`：全部 `"0"`（本次无已找到者）
- `foto`：525 条全带照片；但**格式三种混用** —— 416 条 JPEG（`ffd8ff`）、105 条 PNG（`89504e47`）、4 条 **BMP**（`424d`）
- 姓名：`nombreCompleto` 为源站脱敏口径（姓氏缩首字母，如 `María Del Rosario G. G.`）

## 三、设计

### 3.1 表与注册

- 新建 `cases_es`，走既有的 `ensureCountryTable("ES")` 裸建表（本仓库地区表全部为裸 SQL，Drizzle 只声明大陆 `cases`，**无需改 schema**）。
- `src/lib/db/country-helpers.ts` 的 `SYNCED_COUNTRIES` 加 `"ES"`，使其进入 `find-case.ts` / `stats` / `cases/[id]/view` 三个消费方。
- `src/lib/countries.ts` 的 `COUNTRIES` 早已有 ES（`nameZh: 西班牙`，`lang: "en"`、`regionType: "data-cascade"`），无需改动。**注意上游无地点字段**，故 `lost_province` 等一律为空 —— 与韩国部分记录同理，地区筛选对 ES 呈空集，不在本次范围内。

### 3.2 年份切片同步（`src/lib/sync/cndes.ts`）

- 年份区间：`当前年 + 1` 递减至 `1900`（`YEAR_FLOOR`），并发 4 逐年拉取（`mapLimit`），按 `id` 去重（年份过滤天然不跨年重复，`seen` 仅作保险）。
- 字段映射：
  - `id` → `source_id`；新 uuid 作主键
  - `nombreCompleto` → `name`（**原样保留源站脱敏口径**，缺省 `Nombre desconocido`）
  - `genero`：Hombre → 男、Mujer → 女
  - `fechaDesaparicion` → `lost_date`（正则校验 `YYYY-MM-DD`，不可解析则该条计错误并跳过，同韩国做法）
  - `tipoDesaparecido` / `resumenWeb` / `necesidades` / `cuerpo` → 拼进 `feature`（首行 `【西班牙 CNDES · 失踪人口中心】`，后接 类别 / 概况 / 需求 / 办案警队）
  - `source_url` → 详情页 `Detalle-Desaparecido.html?desaparecido=<id>`
- `localizado == "1"`（已找到）不发布：跳过并计数（本次全为 `"0"`，计数为 0）。
- `view_count` / `follow_count` 沿用韩国随机初值（30–800 / 0–25）。

### 3.3 照片转存

CNDES 照片是 **base64 内联、没有按 id 取图的上游端点**，无法像韩国那样做中转路由（韩国是「上游有图但会返回占位图」）。故选 **本地转存**（与卡 02 决策「仅对无法热链的源（韩/西）本地中转」一致）：

- 同步时对 `foto` 做 base64 解码，按**魔数**判格式（JPEG `ffd8ff` / PNG `89504e47` / **BMP `424d`**，源站三种混用），写入 `public/uploads/cndes/<id 小写>.<jpg|png|bmp>`，`photo_urls` 存 `/api/image/cndes/<...>`。
- **不能直接走 `/uploads/` 静态托管**：`next start` 只服务构建时就存在于 `public/` 的资源，运行期新增的文件（本同步正是运行期落盘）访问会 404。因此仿韩国的 `/api/image/safe182/[id]`，新增一条读盘直出的路由 `/api/image/cndes/[file]`，按扩展名给 `Content-Type`、带长缓存，并对文件名做 `^[0-9a-f]{32}\.(jpg|png|bmp)$` 白名单校验以杜绝路径穿越。
- `/public/uploads/cndes/` 已加入 `.gitignore`：照片是运行期落盘的数据，不进仓库。
- 存储目录在 `process.cwd()` 下生成，因此**同步必须在生产目录（部署目录）内执行**，图片才会落到线上可访问的位置 —— 这也是通过生产端的管理端入口触发同步的原因。

> 顺带发现：既有用户上传功能同样是「写 `public/uploads/` 再返回 `/uploads/...`」，在生产下会撞同一个 404（属历史遗留，不在本卡范围，未改动）。

### 3.4 管理端入口

`src/app/api/admin/sync-cndes/route.ts`，与 `sync-korea` 同构：`getAdminFromCookies()` 守卫，未登录 401；`POST {dryRun}` 跑全量，`GET` 跑 dry-run。因一次全量约 90 次年份请求、含数十 MB base64 与磁盘写入，放在管理员会话后而非公开路径。

## 四、验收

- **全量入库**：`cases_es` 行数 = `totalRegistros`（525），`source = 'cndes'`。
- **照片可用**：`public/uploads/cndes/` 落地 525 张（416 JPEG / 105 PNG / 4 BMP），抽查 `/api/image/cndes/<id>.jpg|png|bmp` 经 `http://localhost:3000` 返回 200 且为对应图片类型。
- **姓名口径**：卡片姓名与源站一致（脱敏，姓氏首字母），不做补全。
- 校验：`tsc --noEmit` 0 错、改动文件 `eslint` 0 错。
