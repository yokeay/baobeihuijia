# 首页优化（夜空首屏 / 首滚翻页 / 隐藏滚动条） — 技术方案

需求编号：REQ-202609-0136
分支：`req-202609-0136`

## 一、需求复述

### 第二轮补充（首屏验收后追加）

第一轮上线后验收，追加三条：

1. 夜间那个黑是对的，但**第一页底下还有一大片泛白**，整页看着不完整 —— 第一页要**整页**都是星空，一点白都不留。
2. 第一页（宣传页）和第二页（寻人列表）要**彻底分开**，第二页开始时才进入真正的寻人页面。
3. **按访客本地时间分昼夜**：夜间就是现在这套夜空；白天只留**零星几颗星**，流星照样划，但**白天流星是白色**、夜间是原来那种夜色。

第二轮的取舍（已与需求方确认）：

- 昼夜判定用**访客本地时间**（06:00–18:00 为白天），不依赖服务端时区、不用地理位置接口。
- 白天配色走**近白的浅蓝天**（顶部 `#cfe0f7` → 底部 `#fbfdff`），十来颗淡星，白色流星配淡蓝灰拖尾 —— 白天不追求「蓝天」，只求「不是纯白」。

### 第一轮原始需求

1. 首页第一页 → 第二页在**刷新后的第一次向下滚动**时，要有 PPT 式的**淡进淡出**翻页效果；翻完之后恢复正常**连续滚动**（包括从第二页滚回第一页）。
2. 首页第一页（广告 + 累计统计收入数据）目前是**纯白底，过于单调**，改为**星空 / 流星**动效背景，表达平台的公益愿景。
3. 首页整页**隐藏滚动条**：可以滚，但不显示滚动条。

## 二、现状问题

1. 首页首屏是一块纯白 `bg-white` 区块，只有居中文字 + 两个统计数字，和下面的白色瀑布流页面**在视觉上连成一片**，滚动时没有任何「换了一页」的感知，首屏的存在感很弱。
2. 平台的核心叙事是「让失散的家人被世界发现」——「被发现」这件事和夜空、星光天然同构，而当前的纯白底完全没表达出来。
3. 滚动条常驻右侧（浏览器默认约 15px），在整页浅色、卡片通栏的设计里是一条很突兀的灰色竖条。
4. 历史包袱：早前有过一版**常驻**的 PPT 式整屏翻页，因为破坏了瀑布流的分页加载和自由浏览被回退 —— 所以这次的翻页**只能发生一次**，且必须能自然回到连续滚动。

## 三、设计方向

- **夜空**：底色用径向渐变（顶部 `#141d3c` → 中部 `#0a1024` → 底部 `#04060e`），叠三层高斯模糊的星云辉光（蓝 / 青 / 红），红色那层贴着地平线，呼应品牌中国红；点缀 130 颗星（其中约 1/4 带光晕），3 颗流星周期性划过。第一轮曾在底部加过一道 `#f5fafc` 的「黎明地平线」把夜空接向白色列表页，第二轮按「第一页整页星空」的要求**已删掉**（见 4.5）。
- **翻页**：刷新后的第一次向下滚动 → 首屏整体淡出上移（340ms），**淡出期间页面不跟手滚动**，最后一帧瞬移到第二页顶部，列表淡入（460ms）。整段动画只有一次，结束后监听器全部摘除，之后完全交还给浏览器原生滚动。
- **滚动条**：`html` 上加类，`scrollbar-width: none` / `::-webkit-scrollbar { display: none }`；因为会省掉约 15px 的占位，类必须在**首屏绘制前**由 `layout.tsx` 里的内联脚本打上，否则会看到一次横向跳动。
- **导航栏**：首屏是深夜空，原来的白色毛玻璃导航条压在上面会很脏。停在首屏时导航栏透明、文字转白浮在夜空上；滚到列表页后恢复原来的白色毛玻璃。

## 四、实施方案

### 4.1 新增文件

| 文件 | 作用 |
| --- | --- |
| `src/components/home/Starfield.tsx` | 天空背景（星云 + 星点 + 流星，昼夜共用一套 DOM） |
| `docs/REQ-202609-0136-plan.md` | 本文档 |

`Starfield.tsx` 的星点坐标由模块级的 `mulberry32` 种子随机数生成（种子固定），因此 SSR 与客户端 hydration 得到**完全一致**的 DOM，不会触发 React 19 的 hydration mismatch。每颗星把自己的基础亮度写进 CSS 变量 `--star-o`，闪烁关键帧按这个变量收放，避免所有星同步呼吸。

### 4.2 修改文件

| 文件 | 改动 |
| --- | --- |
| `src/app/page.tsx` | 首屏换夜空外壳 + `Starfield`；挂首次滚动的翻页逻辑；挂滚动条与导航栏状态的 effect |
| `src/app/layout.tsx` | `<head>` 首位内联脚本，首页首屏绘制前打上 `home-no-scrollbar` / `home-hero-top` / `home-day`；`<html>` 加 `suppressHydrationWarning` |
| `src/app/globals.css` | 昼夜两套天空 / 星云 / 星点 / 流星、PPT 淡出淡入关键帧、滚动条隐藏、首屏透明导航栏的覆盖样式 |
| `src/components/layout/Header.tsx` | 给 logo、导航链接、用户区、汉堡按钮加 `site-header-*` 钩子类；去掉 logo 的内联 `color`（内联样式优先级高于一切样式表，留着就没法在夜空上翻成白色） |

### 4.3 关键实现细节

- **只拦一次**：`wheel`（`{passive:false}`）里判断 `window.scrollY > 4 || e.deltaY <= 0` 直接放行 —— 顶部向上滚、页面已经滚下去之后的操作都不触发。移动端用 `touchstart` 记录起点（仅当 `scrollY <= 4`），`touchmove` 位移超过 8px 才触发。触发后 `preventDefault` 吃掉动画期间的滚动事件，动画结束 `detach()` 摘掉三个监听。
- **落点**：`content.getBoundingClientRect().top + window.scrollY - 48` —— 列表顶部正好贴在 48px 吸顶导航条下方，不会露出一条首屏。
- **样式优先级**：项目 CSS 没有写进 `@layer`，在 Tailwind 4 的层叠顺序里**无层级样式恒胜过 `@layer utilities`**，所以透明导航栏的覆盖规则能生效；但反过来说它的作用域必须收紧到 `html.home-hero-top .site-header:not(.site-header-solid)`，否则会波及全站。
- **无障碍**：`prefers-reduced-motion: reduce` 时，星空动画全部停止（保留静态星点），且**翻页逻辑整个不挂载** —— 系统设了减少动效的用户，首页就是普通的连续滚动。
- **移动端高度**：`min-height: 100vh` 兜底，外面套 `@supports (height: 100dvh) { min-height: 100dvh }`。`dvh` 始终等于当前可视高度，地址栏收起时首屏也还是满的（用 `svh` 的话地址栏一收就会在底下露出一条白，正是第二轮要消灭的那类缝隙）。
- **不做的事**：不动数据逻辑（`fetchCases` / 分页 / 筛选 / i18n key 全部逐字节不变），首屏文案与 `LiveTotal` 统计组件照旧，只换外壳。

### 4.4 与旧版常驻翻页的区别（为什么不会再破坏瀑布流）

| | 旧版（已回退） | 本次 |
| --- | --- | --- |
| 触发次数 | 每次滚动都整屏吸附 | 仅刷新后第一次向下滚动 |
| 滚动步进 | 强制一屏一页 | 一次翻页后完全交还原生滚动 |
| 向上滚 | 同样被吸附，卡在第一页 | 原生连续，可正常回到首屏 |
| 分页加载 | 滚动位置被劫持，`onLoadMore` 触发不稳 | 与原生滚动一致，不受影响 |

### 4.5 第二轮：整页铺满 + 昼夜两套天空

**整页铺满。** 首屏本身就是 `min-height: 100dvh` 的一整屏，底下那道 `#f5fafc` 地平线色带是唯一的白 —— 删掉 `Starfield.tsx` 里那个 `absolute inset-x-0 bottom-0 h-28` 的渐变 div 即可。现在第二页的列表**从首屏下沿 1px 处开始**，翻页动画结束正好停在列表顶部，两页是干净的上下关系。

**昼夜两套天空，按访客本地时间。** 判定是 `new Date().getHours()`，06:00–18:00 为白天。两个地方各判一次，必须一致：

- `layout.tsx` `<head>` 里的内联脚本 —— 首屏绘制**前**就把 `home-day` 打到 `<html>` 上，否则会先画一帧夜景再跳成白天。
- `page.tsx` 里的 `isDaytime()` —— 挂载后按真实时间对齐一次（比如跨过 18:00 时打开页面），卸载时清掉。

昼夜不是换一套 React 树，而是**换一套 CSS**：所有白天配色都挂在 `html.home-day` 下（天空底色、星云、星点、流星、标题文案、导航栏）。好处是切色零重渲染，也便于单测里直接 `classList.toggle('home-day')` 验证整套是否跟着翻。

两处实现上必须绕开的坑：

- **内联样式优先级高于任何样式表**，所以星点的颜色 / 亮度**不能**写成 `style={{color, opacity}}` —— 白天规则永远盖不住。改成写进**内联 CSS 变量**（`--star-c` / `--star-o`），由样式表里的 `.hero-star { color: var(--star-c) }` 消费，`html.home-day .hero-star` 就能正常覆盖，不用 `!important`。
- **星星不减 DOM，只藏**。`STAR_COUNT` 还是 130，生成时按 `i % 9 === 0` 打上 `data-day`；白天用 `html.home-day .hero-star:not([data-day]) { display: none }` 只留十来颗。DOM 数量不变，服务端和客户端渲染的节点一一对应，不会引入 hydration 问题。

白天这套的取值：天空 `linear-gradient(180deg, #cfe0f7, #e8f1fa 55%, #fbfdff)`；星点 `#7f96b4`、`opacity: calc(.3 + var(--star-o) * .35)`（压暗压淡，且 `animation: none`，白点在浅蓝底上闪起来像屏幕坏点）；流星 `linear-gradient(90deg, rgba(150,175,205,0), rgba(214,228,244,.85) 62%, #ffffff)`，尾巴那头垫淡蓝灰是为了让白色拖尾在近白底上有边；标题 `#1a2334`、导航栏 `#1c1c1e`。

另一个副作用：内联脚本在水合前改了 `<html>` 的 `class`，React 会拿服务端那份 `className` 来对、报 hydration mismatch。给 `<html>` 加 `suppressHydrationWarning`（与 `next-themes` 同一做法）显式声明这个元素的属性不用校验。

## 五、验证

`scripts/screenshot.py` 会强制 `reduced_motion="reduce"`，而本次的翻页在 reduce 下**按设计不启用**，所以该脚本无法验证翻页。另写了开启动效的 Playwright 校验（**47 项断言**，桌面 1440×900 + 移动 414×896），另有一份昼夜专项（**18 项**）：

1. 滚动条隐藏（`offsetWidth - clientWidth == 0`）且页面仍可滚动
2. 星点 130 / 流星 3 / 星云 3，动画确实在跑，星点亮度逐帧变化，流星定格在可见段时 `opacity > 0.3`
3. 首屏实测平均亮度 < 90/255（不再是纯白）；滚动提示落在夜空上、底色足够暗
4. 首次下滑：`hero-ppt-out` 生效、**淡出期间 `scrollY` 保持 0**、透明度在 0~1 之间；随后列表 `content-ppt-in` 淡入
5. 稳定后 `scrollY` 精确等于「列表顶部 − 48」，动画类摘除、透明度归 1，导航栏恢复毛玻璃
6. 翻页后：一次滚轮 600px → 页面位移 600px；向上滚同样连续；滚回顶部首屏完整、导航栏重新透明、标题转白
7. 顶部向上滚 / 轻点不触发翻页
8. 移动端：`dvh` 铺满不被地址栏撑高；上滑触发翻页且翻页期间不跟手；翻页后指尖每走 40px 页面就走 40px（跟手连续滚动）
9. 第一页整页无白：最底部 40px 的平均亮度 **15.0/255**（夜空），不再有那圈泛白
10. 昼夜两套：把时钟拨到 10:00 → `home-day` 生效、浅蓝渐变、**15/130** 颗星可见、`animation-name: none`、无光晕、流星含 `rgb(255,255,255)`、标题 `rgb(26,35,52)`、底部亮度 **247.3/255**；拨到 23:30 → 夜色渐变、130 颗全在、闪烁、白字、流星是 `rgba(214,230,255,…)`。再直接 `classList.toggle('home-day')` 翻一次，确认整套配色都跟着 class 走

这套校验里有两处写法值得留个记录，否则会变成随机挂：

- **闪烁断言必须先等过 `animation-delay`**。`animation-fill-mode` 是 `none` 且延迟最多到 7s —— 延迟没走完时动画不改样式，星点就停在基础亮度上。3s 左右取样会变成掷骰子，所以先 `wait_for_timeout(7600)` 再取两次比对。
- **这台机器上一帧约 58ms，但一次 CDP 往返要 200~300ms**，而整段翻页只有 800ms。跨进程采样永远在追帧，所以翻页过程改成**页内 rAF 时间线记录**（把 `{t, 淡出类, hero 透明度, 淡入类, 列表透明度, scrollY}` 逐帧存进数组，事后一次性取回断言）；截图则把动画 `pause()` 后把 `currentTime` 定在 40% 处再拍，画面就确定了。

## 六、风险

- 首屏从白底换深底属于**视觉大改**，实际观感需人工在真机上看一眼（尤其是低亮度屏幕下星点是否太淡）。
- 透明导航栏依赖 CSS 层叠顺序（无层级样式胜 Tailwind utilities）。若日后把项目样式收进 `@layer`，这条覆盖会失效 —— 已在规则处收紧作用域，便于排查。
- 滚动条是整页隐藏，并非只在首屏隐藏；这是需求明确要求的（「滚动条一律隐藏掉」）。
- 白天的第一页底部是 `#fbfdff`，和第二页列表的 `bg-gray-50`（`#f9fafb`）几乎同色，翻页接缝在白天比较看不出来 —— 这是「第一天只求不是纯白」的取舍结果，已与需求方确认。
- 昼夜只在**打开页面时**判一次（外加挂载后对齐一次）。长时间挂着页面跨过 06:00 / 18:00 不会自动切色 —— 需求没要求，避免为它引入定时器。
