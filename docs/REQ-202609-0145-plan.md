# 首页两屏彻底分开 — 技术方案

需求编号：REQ-202609-0145
分支：`req-202609-0145`

## 一、需求复述

首页原本是「一整屏天空 + 紧跟其后的寻人列表」拼在同一个文档流里，滚到衔接处会看到上半屏还是宣传页、下半屏已经是列表 —— 两页粘在一起，很不好看。要求：

1. 首页就是**两个页面**：第一页纯宣传页，第二页纯数据列表页。
2. 两页**不能连在一起**。任一时刻要么整屏只显示第一页，要么整屏只显示第二页，不存在「一半一半」的中间态。
3. 第二页内部中间那列列表可以上下滚动。
4. 页面级的滚动只能落在「整屏第一页」或「整屏第二页」上。

需求方确认的三个交互细节：

- 从第二页回第一页：**在列表顶部再往上滚**（不加固定返回按钮）。
- 列表滚动条：**继续保持全隐藏**（照样能滚）。
- 第二页页脚：**保留**，跟在列表末尾随列表一起滚。

## 二、现状

- `src/app/page.tsx` 里 `<Header />` 之后依次是首屏 `<section>`（`hero-screen`）和列表 `<section>`，两者都是普通块级元素、都在 `document` 滚动流里。首屏高度一屏，列表紧贴在它下面 —— **衔接点就是两页粘连的地方**。
- 旧实现只把「第一次向下滚动」拦下来做 PPT 式的整屏淡出/淡入（`heroPptOut` / `contentPptIn` 两个 keyframes + `heroPhase` state + `syncHeader` 按滚动位置切导航栏状态），翻完那一次就把滚动交还给浏览器。所以从第二次滚动开始，用户看到的必然是「上沿还挂着宣传页尾巴」的连续滚动。
- 导航栏透明态原本由 `syncHeader()` 按 `window.scrollY` 判定，首页整页隐藏滚动条由 `html.home-no-scrollbar` 负责。

## 三、设计

### 3.1 用状态翻屏，不用 scroll-snap

没有采用「两屏各一屏高 + scroll-snap 吸附」的写法。理由是 snap 只能约束**停在哪儿**，管不住过程：中途仍是连续滚动，仍会出现两页同屏；吸附失败了就退回粘连。改成**状态驱动的双屏**之后，翻屏是 `screen` 这个 state 的结果，滚动位置从头到尾是 0，中间态在结构上就不存在。

```
.home-viewport   position:relative; height:100dvh; overflow:hidden   ← 整页不滚
└─ main          absolute inset-0
   ├─ section.home-slide.home-slide-hero   z-20   宣传页
   └─ section.home-slide.home-slide-list   z-10   列表页
```

两屏都 `position:absolute; inset:0`，即各自铺满整个视口（连吸顶导航那 3rem 一起盖住，导航栏靠 `z-40` 浮在最上面）。宣传页 z 序在上，翻走时它向上淡出、露出底下的列表页。

### 3.2 翻屏动效

`.home-slide` 过渡 `opacity / transform / visibility` 三项 0.4s。离开的那一屏：

- 宣传页 → `opacity:0; translateY(-28px) scale(.985)`
- 列表页 → `opacity:0; translateY(32px)`
- 两屏都加 `visibility:hidden; pointer-events:none`

`visibility` 参与过渡是刻意的：切完之后那一屏连绘制都停了，星野（星云 / 星点 / 流星）的 CSS 动画跟着一起停，不需要额外的 `display` 切换或 JS 清理。位移方向一上一下，是「翻页」而不是「叠影」。

`prefers-reduced-motion: reduce` 下只把 `.home-slide` 的 `transition` 关掉，**不关翻屏本身** —— 翻屏是进列表页的唯一途径，关掉就把用户关在宣传页里了。

### 3.3 翻屏的触发与吞输入

`goto(next)` 是唯一入口：加一个 `switchingRef` 锁 + 400ms 定时器，翻屏途中把后续滚轮 / 触摸输入 `preventDefault()` 掉，否则一次惯性滚动能连翻两屏。`screenRef` 存当前屏，供挂在 `window` 上、只注册一次的事件回调读取（闭包里读 state 会拿到注册那一刻的旧值）。

三种输入都收敛到同一条规则：

| 输入 | 宣传页 | 列表页 |
| --- | --- | --- |
| 滚轮 | `deltaY > 0` → 进列表页 | 列表**已滚到顶**且 `deltaY < 0` → 回宣传页 |
| 触摸 | 手指往上划超过 8px → 进列表页 | 列表**已滚到顶**且手指往下划 → 回宣传页 |
| 键盘 | `ArrowDown` / `PageDown` → 进列表页 | `ArrowUp` / `PageUp` / `Home` 且列表在顶部 → 回宣传页 |

「列表在不在顶部」是 `listRef.current.scrollTop <= 0`。这条判断同时替代了「记录列表滚动位置」的活儿：回宣传页的唯一路径就是列表停在顶部，所以下次进列表页天然还是从顶部开始，不需要额外的复位。

键盘那条是必须补的：页面本身不滚了，键盘用户没有滚动惯性可用，只剩方向键；在 `INPUT/TEXTAREA/SELECT/contentEditable` 里按键不算。

**导航栏透明态**跟着 `screen` 走（`html.home-hero-top`），不再看滚动位置 —— 页面根本不滚了，看滚动位置没有意义。首帧之前仍由 `layout.tsx` 里的内联脚本先判一次，避免闪一帧。

### 3.4 列表页的内部滚动与吸顶

列表页整屏不滚，滚动全部发生在中间那一列：

```
section.home-slide-list
└─ div[ref=listRef]  no-scrollbar h-full overflow-y-auto overscroll-contain
   ├─ Container.pt-12   ← 避让导航栏的留白放在这里
   │  └─ flex row: CaseSidebar(sticky top-16) + CaseGrid
   └─ Footer           ← 跟在列表末尾，随列表一起滚
```

`overscroll-contain` 让列表滚到底 / 到顶时不再往父级传播。

**一个实测踩到的坑**：避让导航栏的 48px 留白如果写成滚动容器自己的 `padding-top`，它会**叠加到吸顶元素的偏移上** —— 左侧筛选栏（`sticky top-16`）会从 64px 被推到 112px，比旧版低了整整一截。改成把留白放在滚动容器内部的 `Container` 上（滚动容器 `padding: 0`）之后，吸顶栏回到 64px，与旧版逐像素一致。实测数据：

| 布局 | railTop | 滚动容器 padding-top |
| --- | --- | --- |
| 旧（连续滚动） | 64px | — |
| 新（两屏，留白在滚动容器上） | **112px** | 48px |
| 新（两屏，留白移到内容里） | **64px** | 0px |

### 3.5 滚动条隐藏

`scrollbar-width` 不继承，所以给列表容器单独一个 `.no-scrollbar`，与首页整页的 `.home-no-scrollbar` 合并成一条规则（`scrollbar-width:none` + `-ms-overflow-style:none` + `::-webkit-scrollbar{width:0;height:0;display:none}`）。两处都是「照样能滚，只是不画那根条」。

### 3.6 修掉滚动死带

新布局里导航栏是浮在滚动容器**上方**的（不是滚动容器的祖先/后代链上的元素）。光标停在导航栏那一带滚动时，浏览器顺着命中链找不到可滚的祖先，这一下滚轮就白滚了 —— 旧版是文档滚动，不存在这条死带。所以 `onWheel` 里补一条：光标不在滚动容器内时，把增量手动转交给列表（`el.scrollTop += deltaY`），到顶时照样触发回宣传页。

## 五、验收标准

1. 首页整页不可滚动（`documentElement.scrollHeight - clientHeight == 0`）。
2. 任一时刻只有一屏在画，另一屏 `visibility: hidden`。
3. 翻屏过程中页面 `scrollY` 恒为 0；两屏始终占同一个视口矩形（重叠 ≥ 85% 视口高），不存在上下拼接。
4. 翻屏是叠化，中途两屏同时可见。
5. 宣传页铺满整屏（含导航栏后面），导航栏透明；翻到列表页导航栏恢复毛玻璃。
6. 第二页中间列表能上下滚动；滚动时整页不动。
7. 列表没滚到顶时向上滚**不回**宣传页；滚到顶再向上滚才回。
8. 光标停在导航栏上滚，列表照样滚（无死带）。
9. 触屏上划进列表页、列表顶部下滑回宣传页；键盘 `ArrowDown` / `Home` 同理。
10. 惯性连滚只翻一屏，不会翻过头。
11. 左侧筛选栏吸顶在导航栏下方；列表滚到底页脚可见并贴着视口底。
12. 运行期无 JS 报错；`tsc --noEmit` 通过；`eslint` 不新增问题（基线 86 errors / 30 warnings）。

## 七、已知但本次不改

- 宣传页上导航栏的 `backdrop-filter: blur(24px)` 实际仍在生效，尽管 `html.home-hero-top .site-header` 那条规则里写了 `backdrop-filter: none` —— Tailwind 的压缩器把 `none`（等于初始值）整条丢掉了，规则最终只剩 `background` / `border-bottom-color`。这是**改动前线上就有的**（同一份 CSS 在改动前的生产构建上探测结果相同），本次不顺手改，避免把无关风险带进这次合并。
