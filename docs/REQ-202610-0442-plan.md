# 案例页 SEO 补全：sitemap 覆盖与 hreflang — 技术方案

需求编号：REQ-202610-0442
分支：`req-202610-0442`

## 一、需求复述

路线图卡 14（`docs/REQ-202610-0267-development-roadmap.md`，阶段二）：案件页已有 canonical、JSON-LD（Person）与 OG 元数据；但 sitemap 仅覆盖大陆 `cases` 且**截断 10,000 条**，美国 26,594 条完全不在 sitemap；无 hreflang。目标：① sitemap 分片覆盖全部已同步区表 ② 补 hreflang ③ 核查 robots 与搜索引擎索引状态。验收：sitemap 索引可枚举全部区表条目，hreflang 输出正确。

（注：卡撰写时站点为 10 语言；REQ-202610-0449 西语包合入后为 11 语言，本卡一并覆盖 `es`，否则西语页将成为 hreflang 空缺。）

## 二、现状（实测）

- 旧 `src/app/sitemap.ts`：drizzle 只查 `cases` 单表，按 `updatedAt` 倒序 `LIMIT 10000`。美国（26,594 条）、香港（40 条）、韩国（1,043 条）、西班牙（525 条）完全缺席；大陆 46,908 条只收录 10,000。
- `src/app/robots.ts` 实测已正确：`Allow: /`、`Disallow: /admin/ /api/`、Baiduspider `Crawl-delay: 1`、`Sitemap: https://wohaoxiangni.com/sitemap.xml` —— 无需改动。
- Next.js 16.2.9（Turbopack）sitemap 机制（以 vendored 文档 + 构建实测为准）：
  - `generateSitemaps()` 返回 `{ id }[]`，分片服务在 `/sitemap/<id>.xml`（metadata 路由对 `__metadata_id__` 要求 `.xml` 后缀，`generateStaticParams` 会 push `id + '.xml'`）；
  - Next **不自动生成 sitemap 索引**；
  - `app/sitemap.xml/route.ts` 与 `app/sitemap.ts` 并存会被构建直接拒绝（`Conflicting route and metadata at /sitemap.xml`）——sitemap 元数据路由已占用该路径，索引不能放这里。

## 三、设计

### 3.1 分片规划（`src/lib/sitemap-shards.ts`，新增）

- 覆盖区表：CN（`cases`）+ `SYNCED_COUNTRIES`（US/HK/KR/ES），与数据源同步范围单一来源绑定；
- 每 2 万条一片，按 `id ASC` 稳定切分——部署之间分片边界不漂移，爬虫不会看到 URL 在分片间搬家；
- 实测结果 **9 片**：`pages`（4 个静态页）、`cn-0/1/2`、`us-0/1`、`hk-0`、`kr-0`、`es-0`；
- 合计 **75,114 URL**（75,110 案件 + 4 静态页），单文件远低于协议上限（50,000 URL / 50MB）；
- 分片 id 形如 `<region>-<n>`，可读、可直接进日志排查。

### 3.2 sitemap 分片（`src/app/sitemap.ts`，重写）

`generateSitemaps()` 输出分片清单；默认导出按 id 渲染：`pages` → 静态页（home/submit/terms/privacy）；区片 → 该区 `approved` 案件（`LIMIT/OFFSET` 原始 SQL，与多国表工具 `getCasesTableName` 共用表名规则）。DB 不可用时只降级为静态页分片，不打断构建（沿用旧实现的兜底思路）。

### 3.3 索引与规范地址

- 索引路由放 `src/app/sitemap-index.xml/route.ts`（`force-static`，构建期快照），输出 `<sitemapindex>` 列出全部分片；
- `next.config.ts` 增加 fallback rewrite：`/sitemap.xml` → `/sitemap-index.xml`。robots.txt 与搜索引擎指向的规范地址 `/sitemap.xml` 保持不变，对外无感；
- 未知分片 id → 404（Next 元数据路由天然行为，已实测）。

### 3.4 hreflang（`src/lib/i18n/hreflang.ts`，新增）

- 站点是「单 URL + 客户端语言状态」结构，故 hreflang 变体 = 同 URL 加 `?lang=<code>`；`zh-CN` 与 `x-default` 用裸 URL，其余 10 种语言用查询参数；
- 导出：`HREFLANG_VARIANTS`（11 语言）、`variantUrl`、`languageAlternates`（11 语言 + x-default）、`langFromQuery`（归一化 `?lang=` 值，大小写不敏感，未知值返回 null）；
- 首页（`layout.tsx`）与每个案件页（`generateMetadata`）输出 `alternates.languages`，实测各 12 条 `<link rel="alternate">`；
- `?lang=` 的客户端应用（`public-context.tsx`）：挂载后一次性读取并应用。不用 `useSearchParams`（会给全站每页带来 CSR bailout）；不在渲染期应用（会与静态 HTML 的中文默认值水合不一致）；`react-hooks/set-state-in-effect` 单行豁免并注明理由（该规则针对循环，这里是一次性后水合应用）；
- JSON-LD `inLanguage` 补齐 `ug/mn/bo`（`es` 由 0449 补入）。

### 3.5 有意不改

- **sitemap 内不写 hreflang alternates**：单 URL 变体方案下 `<link rel="alternate">` 已完整覆盖，sitemap 只负责 URL 发现；避免同一事实两处声明、两处维护；
- `robots.ts` 不改（实测已正确）；
- 案件页服务端 meta 标题模板仍只覆盖 zh/en（不属本卡）。

## 五、验收标准

1. `/sitemap.xml` 返回合法 sitemapindex，列出全部分片；
2. 各分片合计 = 全部已同步区表 `approved` 案件（不再截断、不遗漏区表），且无重复；
3. 每个分片 ≤ 50,000 URL、XML 合法（urlset + lastmod/changefreq/priority）；
4. 首页与案件页输出 11 语言 + x-default 的 hreflang，canonical 不变；`?lang=` 实际能切语言（含 es），未知值回退默认；
5. `tsc` / `npm run lint`（不超基线 86 errors / 30 warnings）/ `npm run build` 全绿；
6. 合并 `local-server` 并部署后线上复验通过（结果见文末补记）。

## 七、已知但本次不改

- sitemap 为构建期快照（分片 SSG + 索引 force-static）：新审核通过的案件在下次构建部署后进入 sitemap；站点数据本就随部署更新，节奏一致。
- `?lang=` 为客户端应用：首帧（静态 HTML）为中文，水合后切换；hreflang 声明在静态 HTML 中输出，爬虫不受影响。
- 搜索引擎索引状态：服务器侧无法查询各引擎索引库；已核查 robots 允许抓取、页面无 noindex、sitemap 与 hreflang 均可被公开抓取——收录进展需在 Search Console / 站长平台侧观察（卡内 ③ 项以「核查」交付）。
- ug/mn/bo 语言包仍为机翻占位（既有待办，与本卡无关）。
